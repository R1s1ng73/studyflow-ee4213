# Three-Participant Usability Test Guide

## Session setup

- Use the same browser and viewport for comparable sessions; 390px mobile is recommended for the mobile project task scenario.
- Restore the agreed demonstration dataset before each participant session only when the research protocol permits it.
- Explain that records and team updates are fictional, local to the browser, and not live collaboration data.
- Ask participants to think aloud without teaching them where controls are.
- Record observable behavior, direct participant wording, task completion, errors, and recovery. Keep interpretation separate from observation.

## Workflow 1 — Capture and change a deadline

1. Add a new assignment with a course, assessment type, date, and date meaning.
2. Locate it in Deadlines and Calendar.
3. Change its date from the Calendar event.
4. Confirm the same record moves across views.
5. Delete the test record.

Observe: whether required fields, optional details, confirmation, and edit/delete controls are understood.

## Workflow 2 — Choose work for 30 minutes

1. Open My Tasks and select Short Tasks.
2. Choose 30 minutes.
3. Explain which task they would choose and why.
4. Add a missing estimate when prompted.
5. Mark a task Done, then reopen it.

Observe: whether duration filtering, overdue text, missing-estimate recovery, and completion reversal are understood.

## Workflow 3 — Review a delayed group project

1. Open Group Projects on a mobile viewport.
2. Use Needs attention.
3. Identify the owner, internal deadline, reported status, last update, and blocker.
4. Update the reported status.
5. Explain what changed in project progress.

Observe: scan order, interpretation of “reported” status, attention reasons, and confidence using the mobile cards.

## Workflow 4 — Understand the academic schedule

1. Review Dashboard deadlines and Quick Wins.
2. Open Calendar and navigate to the next month, then return to Today.
3. Find an exam and identify whether its date is a scheduled start or submission deadline.
4. Return to My Tasks and describe the next work they would do.

Observe: consistency across views, date meaning recognition, navigation, and whether overdue work is noticed.

## Post-session questions

- What felt easiest and hardest?
- At any point, what did you expect to happen instead?
- Which information helped you decide what to do next?
- Did any label or status feel ambiguous?
- What single change would most improve the dashboard?

## Analysis guidance

With three participants, report recurring observations and notable individual breakdowns without presenting them as statistically representative. Only add “participant feedback” changes to the iteration log when supported by actual session evidence.
